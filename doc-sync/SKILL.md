# doc-sync - Word·PPT 에서 고친 것을 코드로

도구: `python -X utf8 ~/.claude/skills/doc-sync/docsync.py <명령>` (표준 라이브러리만)
결과물은 문서 옆 `_docsync/<문서 이름>/` 에만 남는다(base.json·원본 사본·diff_시각.md/.json·history/). 고객 자료 폴더 밖으로 옮기지 않는다.

## 원칙
- 찾기는 도구가, 고치기는 Claude 가, 확인은 다시 도구가 한다. 바뀐 점과 남은 차이는 도구 출력을 그대로 쓴다.
- 사용자가 고친 문서는 덮어쓰지 않는다. 다시 만든 문서는 임시 경로에 쓰고 `verify` 로만 비교한다.
- `verify` 가 차이 0 을 내기 전에는 "반영 완료"라고 말하지 않는다. `--ignore` 를 쓰면 무엇을 왜 뺐는지 보고에 적는다.

## 1. 기준본 남기기 - Word·PPT 를 만들거나 고친 직후
`docsync.py snap <문서> --label "<차수·설명>"`. 기준본이 있으면 `office-guard` 가 "기준본과 같으면 다시 만들어도 된다"고 판단한다.

## 2. 사용자가 고쳤다고 할 때
1. `docsync.py status <문서>` - 바뀌지 않았으면 그렇게 답하고 끝.
2. `docsync.py diff <문서> --code <코드 폴더>` - 표를 읽는다. 열: 종류 · 위치 · 전 · 후 · 칸 · 반영 · 코드.
3. 변경마다 반영한다. '반영' 열의 뜻:
   - 코드 수정: 코드에 같은 글이 있다. 그 줄을 고친다.
   - 칸 값 확인: `word_fill`·`ppt_fill` 칸 안의 값이다. 넘기는 데이터를 고친다.
   - 양식에 유지: 코드에 없는 글·서식이다. 양식 방식이면 양식에 그대로 남으므로 옮길 일이 없다. 코드가 문서 전체를 그리는 빌더면 그 부분을 양식 방식으로 바꾸거나 코드에 넣는다.
4. 생성 코드를 임시 출력 경로로 실행한다.
5. `docsync.py verify <사용자가 고친 문서> <다시 만든 문서>` - 0 이 될 때까지 3~5 반복.
6. 끝나면 `docsync.py snap <사용자가 고친 문서> --label "..."`.
7. 보고(짧게): 바뀐 점 요약 · 반영 방법 · verify 결과 · 남은 차이와 이유.

## 빌더 없이 저장본을 고치는 건
몇 곳만 고칠 일은 그 문서를 불러와 해당 문단·칸만 고쳐 같은 경로에 저장한다. 끝나면 snap.

## 한계
- 문단 맞춤은 글 유사도 기준이라, 문단 대부분을 다시 쓰면 고침 대신 삭제와 추가로 나온다.
- 코드 위치는 글이 코드에 그대로 있을 때만 찾는다. 변수로 조립한 문장은 달라진 조각과 숫자를 뺀 가장 긴 조각으로 다시 찾는다.
- Word 의 그림은 개수만, 도형 안 서식과 머리글의 그림은 비교하지 않는다. 변경 내용 추적의 지운 글은 없는 글로 본다.
- PPT 의 글 맞춤 도형은 PowerPoint 가 크기를 다시 정하므로 위치만 비교한다. 슬라이드 레이아웃·전환 효과는 비교하지 않는다.
