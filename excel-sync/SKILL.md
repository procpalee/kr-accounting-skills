# excel-sync - 엑셀에서 고친 것을 코드로

도구: `python -X utf8 ~/.claude/skills/excel-sync/xlsync.py <명령>` (openpyxl·olefile, 엑셀 재저장 비교는 pywin32 + 엑셀 필요)
결과물은 엑셀 파일 옆 `_xlsync/<파일이름>/` 에만 남는다(base.json·원본 사본·prov.json·diff_시각.md/.json·history/).
snap 은 새 기준본을 임시 파일로 다 만든 뒤에만 옛 것을 history/ 로 보낸다 - 도중에 실패해도 기존 기준본은 그대로다.

## 원칙
- **찾기는 도구가, 고치기는 Claude 가, 확인은 다시 도구가.** 바뀐 점 목록·코드 위치·남은 차이는 도구 출력을 그대로 쓰고 추측하지 않는다.
- 사용자가 고친 엑셀은 **절대 덮어쓰지 않는다.** 코드로 다시 만든 파일은 임시 경로에 쓰고 `verify` 로만 비교한다.
- `verify` 가 차이 0 을 내기 전에는 "반영 완료"라고 말하지 않는다. 남은 차이는 목록 그대로 보고하고 이유를 붙인다.
- `--ignore` 를 쓰면 무엇을 왜 뺐는지 보고에 적는다.

## 1. 기준본 남기기 - Claude 가 엑셀을 만들거나 고친 직후 (매번)
- 생성 스크립트가 있으면 기록을 켜고 실행: `xlsync.py record --prov <임시>/build.prov.json -- <빌드.py> [인자]`
  (COM 후처리·체크박스 부착 같은 단계는 그다음 평소대로)
- 최종 파일로 기준본: `xlsync.py snap <최종 엑셀> --prov <임시>/build.prov.json --label "<차수·설명>"`
- 생성 스크립트가 없는 파일(사람이 만든 템플릿 등): `xlsync.py snap <엑셀> --label ...`
- 생성 코드가 출력 경로를 고정해 두었으면 임시 경로를 받을 수 있게(인자·환경변수) 먼저 고친다 - 검증용 재생성이 사용자가 고친 파일을 덮어쓰면 안 된다.
- 기준본은 파일 옆 `_xlsync/` 에 남으므로 고객 자료 폴더 밖(깃 저장소 등)으로 옮기지 않는다.
- 사용자에게 "엑셀에서 고치고 저장한 뒤 알려 주면 바뀐 부분을 찾아 코드에 반영한다"고 한 줄 안내.

## 2. 사용자가 고쳤다고 할 때
1. `xlsync.py status <엑셀>` → 바뀌지 않았으면 그렇게 답하고 끝.
2. `xlsync.py diff <엑셀> --code <코드 폴더>` → 표를 읽는다(문구 검색은 코드·설정 파일만 - .md·.txt·.csv·한 줄짜리 덤프 제외, 생성 기록이 있으면 --code 생략 시 그 스크립트 폴더). 열마다: 종류 · 위치(현재 주소) · 기준 위치 · 전→후 · 코드(쓴 곳 = 생성 기록의 파일:줄, 문구 = 코드에 같은 문자열이 적힌 줄).
3. 변경마다 반영 방법을 정한다.
   - **코드 수정**: 쓴 곳/문구 위치가 상수·문구 표·서식 헬퍼·열너비 설정이면 그 줄을 고친다(같은 패턴이 여러 칸에 쓰이는지 확인 - 한 칸만 바꾼 경우는 아래 목록으로).
   - **덮어쓰기 목록**: 한두 칸만 다른 값·서식·열너비·병합은 `xlsync.py overrides <diff_...json> --out <코드폴더>/overrides.json`
     → 생성 코드 저장 직전에 한 번만 추가:
     `sys.path.insert(0, os.path.expanduser("~/.claude/skills/excel-sync")); from xlsync_overrides import apply_overrides; apply_overrides(wb, "<코드폴더>/overrides.json")`
   - **직접 반영**: 행·열 삽입/삭제, 시트 추가·이름 변경, 체크박스·VBA·그림·조건부 서식은 생성 코드 구조를 고친다(diff 의 행 이동표 `maps` 참고).
     같은 시트에 행·열 구조 변경이 있으면 그 시트의 덮어쓰기 목록은 만들지 않는다 - 구조를 먼저 코드에 반영하고 다시 diff.
4. 다시 만들기: 생성 스크립트를 **임시 출력 경로**로 실행(가능하면 `record` 로 기록도 갱신) + 원래 후처리.
5. `xlsync.py verify <사용자가 고친 엑셀> <다시 만든 엑셀>` → 0 이 될 때까지 3~5 반복. 도구가 비교하지 못하는 항목(아래 한계)은 따로 확인.
6. 끝나면 새 기준본: `xlsync.py snap <사용자가 고친 엑셀> --prov <새 기록> --label "..."`.
7. 보고(짧게): 바뀐 점 요약(시트·범위) · 반영 방법(코드 줄 / 덮어쓰기 목록 / 직접 반영) · verify 결과 · 남은 차이와 이유.

## 생성 코드가 없는 파일(템플릿이 원본)
diff 로 바뀐 점과 행·열 이동표를 보여 주고, 그 파일을 읽거나 채우는 코드(로더·검증 스크립트)에 박힌 주소·시트 이름을 이동표대로 고친 뒤 snap.

## 한계(보고 때 필요하면 언급)
- 행 맞춤은 값 기준이라, 빈 줄만 넣거나 같은 값 줄이 반복되면 삽입 위치가 한 줄 어긋나 보일 수 있다(값 비교에는 영향 없음).
- 차트·그림·도형·양식 컨트롤은 개수만, 피벗·슬라이서·x14 확장 유효성·스파크라인은 비교하지 않는다.
- 이진 파트(엑셀 COM 으로 인쇄 영역·페이지 설정을 바꾸면 생기는 `printerSettings*.bin`, OLE 개체·시트 배경 그림)는 sha256 으로 같음/바뀜만 본다(종류 `binary`).
  다른 PC 프린터로 만든 인쇄 설정은 엑셀로 저장만 해도 이 PC 기본 프린터 것으로 바뀌어 '바뀜'이 나올 수 있다(방향·용지는 그대로).
  openpyxl 은 이 파트를 만들지 못하므로 verify 에 '→ (없음)' 이 남으면 COM 후처리로 맞추거나 `--ignore binary` 로 빼고 이유를 적는다.
  옛 기준본(2026-09-30 이전 snap)과는 이 항목을 건너뛰고 '참고' 줄로 알린다 - 다시 snap 하면 비교.
- 엑셀 재저장(정규화)은 pywin32 와 엑셀이 있어야 한다. 없으면 openpyxl 산출물과 엑셀 저장본 사이에 기본 글꼴·열너비 흔적이 차이로 나올 수 있다.
- 계산 결과 값(캐시)·선택 칸·확대율은 비교하지 않는다.
