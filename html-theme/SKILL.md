# html-theme — 정리 페이지 표준 테마

"정리해줘"류 요청의 HTML 페이지(Artifact)를 **항상 같은 디자인·구조**로 만들기 위한 스킬.
디자인은 사용자가 확정한 **C안 Hybrid**(화이트 베이스 + 네이비 헤더바 + 절제된 블루 액센트, Pretendard).

## 절차

1. `artifact-design` 스킬을 먼저 로드한다(Artifact 작성 전 필수).
2. 요청 유형에 맞는 **구조 프리셋**을 고른다(아래 표). 애매하면 가장 가까운 것을 변형.
3. `templates/<프리셋>.html`의 골격을 복사하고, `<style>` 자리에 **`html_theme.css` 전체를 인라인**한다
   (Artifact CSP상 외부 CSS 불가 — css 파일이 단일 소스, 템플릿에는 붙여넣기 자리만 있음).
4. 내용을 채워 **스크래치패드**에 저장 후 Artifact 툴로 게시.
   같은 주제 갱신 시 **같은 파일 경로로 재게시**해 URL 유지.
5. 채팅에는 링크 + 핵심 3줄만.

## 구조 프리셋

| 프리셋 | 트리거 | 섹션 순서 |
|---|---|---|
| `compare` | 비교해줘 / 차이 알려줘 | 히어로 → 핵심 요약 → 비교표(차이 하이라이트) → 항목별 상세 → 결론·권고 |
| `review` | 검토 결과 / 이슈·문제점 보여줘 | 히어로 → KPI 요약 → 문제점 카드 → 해결책·권고 → 후속 조치 체크 |
| `steps` | 어떻게 했는지 / 구현·작업 정리 | 히어로 → 개요 → Step 카드(산출물 링크) → 고려사항 체크리스트 |

프리셋에 없는 유형(예: 단순 목록·FAQ)은 히어로 + 섹션 구조만 유지하고 컴포넌트를 조합한다.

## 컴포넌트 (html_theme.css)

| 클래스 | 용도 |
|---|---|
| `.wrap` | 본문 컨테이너 (max 860px) |
| `.hero` + `h1` + `.sub` | 제목부 — 네이비 상단바. sub에 `회사 · 기준일 · 작성자` |
| `.kpis > .kpi (.n/.l)` | 숫자 요약 카드 |
| `h2 > .no` | 섹션 번호(블루) — **실제 순서가 있을 때만** 번호 사용 |
| `.scroll-x > .tbl` | 표 — 네이비 삼선표. 넓은 표는 반드시 `.scroll-x`로 감싼다 |
| `.tbl .num` | 숫자 열(우측 정렬·tabular-nums) |
| `.neg` | 음수·경고 — 음수는 빨간 괄호 `(1,200)`, 0은 `-` (회계 관례) |
| `.old` / `.new` | 비교: 기존(회색) / 변경 후(굵게) |
| `.diff-del` / `.diff-add` | 삭제(취소선) / 추가(블루) |
| `.badge` (`-warn`/`-ok`) | 상태 배지 (판단·규칙·검토필요 등) |
| `.callout` | 핵심 메시지 박스 |
| `.card`, `.grid2/.grid3` | 이슈·항목 카드와 그리드 배치 |
| `.step > .step-no` | 단계 카드 |
| `.check` | 체크리스트 |
| `.footnote` | 각주 — **익명화 표기 필수 위치** |

## 규칙

- **익명화**: 고객 실데이터가 섞이면 고객사명·개인명을 A사/B사 등으로 바꾸고
  `.footnote`에 "고객사명은 익명 처리했습니다" 명시. 금액·계정과목은 유지 가능.
- **다크 모드**: css에 이미 `prefers-color-scheme` + `data-theme` 오버라이드 포함 —
  색을 추가할 때는 반드시 토큰(`var(--…)`)으로만. 하드코딩 hex 금지.
- **폰트**: Pretendard 스택 유지(CDN 로드 금지 — CSP 차단됨. 로컬 설치 폰트 + 맑은 고딕 폴백).
- 색 토큰은 word-theme procpa 계열과 정합: navy `#0B1C4A`, blue `#2563EB`, band `#EFF5FF`, negative `#C0392B`.

## 파일

- `html_theme.css` — 토큰·컴포넌트 단일 소스 (수정은 여기서만)
- `templates/compare.html` · `review.html` · `steps.html` — 구조 골격
- 메일 초안이 필요하면 → `email-draft` 스킬 (별도)
