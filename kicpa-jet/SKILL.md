# kicpa-jet - 분개 및 기타 조정사항 테스트(한공회 3600 18(1))

한공회 2026 표준조서에는 분개테스트 별첨 서식이 없고 3600 부정의 검토 18(1) 1)~3) · 19 · 29(2)에 요구사항만 있다.
이 스킬은 그 요구사항을 맨 앞 요약 시트로 두고 시나리오 · 모집단 · 선정 결과를 별첨 조서(기본 **3600D**, 3600A~C 질문서 다음)로 만든다.
건마다 번호가 다르면 `--wp-no 6200` 처럼 바꾼다.

## 도구 (`python -X utf8 <도구>.py …`)
| 도구 | 하는 일 |
|---|---|
| `jet_build.py` | 분개장 + TB → 3600D 조서 + `<조서>_summary.json`(파이썬 판정 건수 · 완전성 차이) |
| `jet_check.py` | LibreOffice 로 재계산해 엑셀 수식 결과(시나리오 건수 · 줄 수 · 차변 합계 · 완전성 차이 계정)가 파이썬과 같은지 대조 |
| `jet_rules.py` | 시나리오 정의 · 기본 파라미터 · 파이썬 판정(조서 수식과 같은 규칙) |
| `make_example.py` | 가상 회사 예시 자료(가나상사 K-IFRS 도소매 · 다라정밀 일반기준 제조, 더존 분개장 + TB csv) |
| `holidays.json` | 연도별 공휴일(30 선정기준 목록으로 들어가 사람이 고침) |
| `kicpa_core/` | 팩 공통 - 분개장 읽기 · TB 읽기 · 계정 분류 · IFRS/K-GAAP 과목 골격 · 조서 부품 · 재계산 · 행높이 맞춤 |

## 만들기
```
python -X utf8 jet_build.py --journal <분개장 파일 | 폴더 | 와일드카드> --company <회사명> --year-end 2026.12.31 --gaap ifrs|kgaap
      (--tb <xlsx|csv> | --tb-dir <xlaudit tb 폴더> --tb-date 2026.06.30 --tb-prior-date 2025.12.31 | --tb-json <douzone_tb json>)
      [--start 2026-01-01] [--end 2026-06-30] [--pm 819000000] [--author 이름] [--wp-no 3600D] [--list-max 100] --out <xlsx>
python -X utf8 jet_check.py <조서.xlsx>
```
- 분개장: 폴더를 주면 그 안 엑셀 · csv 를 모두 합친다(반월 파일 12개 등). 파일마다 '합계' 줄이 있으면 20 시트에서 대사한다. 원본은 읽기만.
- TB 표 머리글: 계정코드 · 계정과목 · [구분(자산 · 부채 · 자본 · 손익)] · 기초(전기말) · 기말. 금액은 차변 +.
- 수행중요성은 2700 조서 값을 `--pm` 으로. 없으면 임시값(자산 · 연환산 매출 중 큰 값 × 0.5% × 75%)이 들어가고 경고가 나온다 - 사용자에게 알린다.
- 산출이 이미 있으면 멈춘다(사용자가 고쳤을 수 있음). 확인 후에만 `--overwrite`.
- 줄이 많으면 오래 걸린다(26만 줄: 만들기 2분 30초 · 65MB, 재계산 대조 6분) - 백그라운드로 돌린다. 100만 줄이 넘으면 기간을 나눈다.

## 조서 구조 (excel-theme `audit`)
| 시트 | 내용 | 사람 칸(크림) |
|---|---|---|
| 3600D | 1. 기본 정보 · 2. 한공회 3600 요구사항(18(1) 1)~3) · 19 · 29(2), 조서번호 = 상세 시트 링크) · 3. 테스트 요약(수식) · 4. 결론 | 수행자 · 비고 · 예외 수 · 결론 |
| 10 재무보고절차 이해 | 담당자 인터뷰 · 분개 생성/승인/권한 · 관여자 질문 ①②③(3600C 연계) · 월별 분개 분포(수식) · [전표 유형 분포] · 결론 | 전부 |
| 20 모집단 완전성 | 파일별 줄 · 합계와 원본 '합계' 줄 대사 · 데이터 필드 · 계정별 기초 + 차변 - 대변 = 기말(TB) · 검증 요약(차이 합계 포함) | 입수일 · 차이 사유 |
| 30 선정기준 | 기본 · 시나리오별 파라미터(이름 정의 칸) · 공휴일 · 키워드 · 계정 목록 · 시나리오 표(한공회 18(1) 2) 보고기간말 / 3) 기간 전체 구분) · 결론 | 파라미터 · 목록 · 적용 O/X · 선정 사유 · 추출 결과 |
| 40 선정분개 테스트 | 시나리오별 추출 전표(차변합계 큰 순, `--list-max` 건까지) · 매출 · 대여금 상대계정 분석표 | 증빙 확인 · 사업상 근거 · 검토 결과 |
| Data_전표 · Data_분개장 · Data_TB | 전표 단위 판정(수식) · 분개장 원본 줄 · TB(대사 계정 칸) | Data_TB 대사 계정 |

- **완전성 대사 계정**: TB 에 없는 분개장 보조 계정은 끝자리를 0 으로 채운 TB 계정에 모은다(1030001 → 1030000). Data_TB '대사 계정' 칸에서 고치면 20 시트가 다시 계산된다.
- **이익잉여금 줄**: TB 대차로 두 칸을 자동으로 정한다(30 시트 1. 기본 파라미터) - '기초 이익잉여금에 전기 손익 더함'(TB 가 손익을 따로 두는 형식, xlaudit TB 등) · '기말 이익잉여금에 당기 손익 포함'(더존 마감 후 재무상태표). 제조원가 계정은 매출원가에 이미 들어 있어 손익 합계에서 뺀다.
- 마감 대체 전표 = 400 손익 계정이 든 전표(30 '마감 대체' 목록). 원가 대체 전표 = 재공품 차변 + 제조원가 대변.
- 40 의 전표 목록은 **만들 때의 파라미터로 뽑은 값**이다. 파라미터를 크게 바꾸면 Data_전표 '추출 시나리오' 열로 거르거나 다른 `--out` 으로 다시 만든다.
- 시나리오 JS10 · JS11 은 분개장에 작성일(입력일) 열이 있을 때만 적용 O.

## 넘기기 전
1. `jet_check.py` 결과 '모두 일치'.
2. `theme_lint.py <조서> audit` · `excel-theme tools/render_check.py <조서> <Data_ 를 뺀 시트…>` 위반 0. 행높이는 `kicpa_core.wp.fit_rows`(줄바꿈 칸 자동 맞춤 → 병합 칸 fit_merged_rows, Data_ 시트는 건너뜀).
   - 린트의 '번호 뒤 공백'이 Data_분개장 · 40 시트 적요 칸에서 나오면 회사 원자료 적요('1.가나' 등)라 고치지 않는다(증빙 원문 보존) - 보고에 한 줄로 적는다.
   - 수십만 줄 조서는 검증 도구가 통째로 읽어 메모리를 많이 쓴다(70MB 에 약 10GB) - 다른 숨은 엑셀(/automation)이 남아 있지 않은지 먼저 본다.
3. 20 완전성 차이를 사용자에게 보인다 - 짝을 이루는 차이(선급금 ↔ 외상매입금, 부가세대급금 ↔ 예수금 등)는 TB 가 정산표 수정 후 금액일 때 생긴다. 회사 ERP 합계잔액시산표를 TB 로 쓰면 줄어든다.
4. `excel-sync` 로 기준본.

## 지키는 것
- 사람 칸(프로세스 이해 · 선정 사유 · 추출 결과 · 증빙 확인 · 결론 · 차이 사유)은 비워 둔다.
- 계산값은 모두 수식. 값은 원자료(분개장 · TB) · 파라미터 · 텍스트뿐.
- 스킬 폴더 · 예시에 고객사명 · 실데이터를 넣지 않는다(예시는 `make_example.py` 가상 자료).

## 시험 기록
- 실무 자료(K-IFRS, ERP형 반월 분개장 12개 · 반기 26만 줄 · 전표 8만 건): 시나리오 11종 · 완전성 차이 계정이 엑셀 재계산과 모두 일치, 오류 칸 0. 차이는 대부분 정산표 재분류 짝.
- 가상 2개사(더존형, 1,745 · 1,829줄): 완전성 차이 0, 심은 시나리오가 모두 걸림, 재계산 대조 일치.
