# 업무 자동화 스킬 만들기 (work-skill-creator)

사용자가 반복하는 업무 하나를 **업무 스킬** 하나로 만든다.
업무 스킬 = 매번 같은 일을 하는 코드(`scripts/`) + 언제 무엇을 사람에게 물을지 적은 `SKILL.md`.

## 기본 원칙
1. AI는 확률 모델이라 같은 요청에도 결과가 매번 달라진다. 1원까지 같아야 하는 반복 업무는 **코드로 고정**한다.
2. 코드는 클로드가 쓴다. 사용자는 코드를 쓰지 않고 **읽고 · 다시 돌리고 · 결과를 확인**한다.
3. **반복은 코드, 해석은 클로드, 결정은 사람.** 클로드는 근거를 붙인 초안까지 내고, 결과에 책임이 따르는 결정은 사람에게 묻는다.

맞게 만들었는지는 **지난번에 사람이 만든 완성본**으로 확인한다. 같은 원자료로 다시 만들어 차이가 0이면 그 방법을 스킬로 저장한다.

## 이 스킬에서 쓰는 말
| 말 | 뜻 |
|---|---|
| 작업 폴더 | 그 업무를 하는 폴더. 없으면 `01_받은자료`(읽기만) · `02_작업` · `03_산출` 로 만든다. 사용자 폴더 체계가 있으면 그것을 쓴다 |
| 완성본 | 사람이 만들어 실제로 제출 · 확정한 판의 결과 파일(중간 판 아님) |
| ① 지난 기간 완성본 | 정답 기준. 계산 결과 칸의 값은 비교에만 쓴다 |
| ③ 그 전 기간 완성본 | **틀** - 재현 시험에서 사본으로 이어받는 원본 |
| 판단 입력 | 사람이 정한 것만 적는 파일 `02_작업/판단입력_<기간>.json` |
| 재현 시험 | 지난 기간 원자료로 코드가 지난 기간 결과를 다시 만들어 ①과 칸마다 비교하는 것 |
| 이름표 | '합계' · '1. 차입금' 처럼 칸에 적힌 제목 글자. 코드는 행 번호 대신 이름표로 위치를 찾는다 |
| 뼈대 | `new_task_skill.py` 가 만드는 업무 스킬의 빈 틀(SKILL.md · build.py …) |

## 준비물
윈도우 + 데스크톱 엑셀(다시 계산 · 엑셀 직접 조작), 파이썬 3.11 이상, `python -m pip install openpyxl pywin32` (워드 · PPT 결과물이면 `python-docx python-pptx` 도).
도구는 이 SKILL.md 가 있는 폴더의 `scripts/` 에 있고 `python -X utf8 "<이 스킬 폴더>/scripts/<도구>.py"` 로 돌린다(`-X utf8` = 한글 윈도우에서 글자가 깨지지 않게).
`python` 이 없으면 `py` 로 해 보고, 그래도 없으면 사용자에게 파이썬 설치를 안내한다. 엑셀을 다루는 명령은 시간 제한을 10분으로 두고 돌린다(큰 파일 재계산).

## 어디서 시작하나
| 사용자 상황 | 시작 |
|---|---|
| "이 업무를 스킬로 만들고 싶어" (처음) | 1단계 |
| 방금 대화로 업무를 끝냈다("방금 한 거 스킬로") | 대화에서 1단계 답(자료 · 순서 · 사용자가 고쳐 준 것)을 뽑아 확인받고 → 2단계(대화 중 만든 코드는 뼈대 build.py 로 옮긴다) → 맞출 완성본이 있으면 3단계, 없으면 대화 결과를 사용자가 확정해 기준으로 삼는다 |
| 만든 업무 스킬을 다음 기간 자료로 돌린다 / 돌리다 걸렸다 | 5단계 |
| 한 건(회사 · 팀)에 반복 업무가 여럿이다 | [references/portfolio.md](references/portfolio.md) 조사표부터 → 업무마다 1~5단계 |
| ①은 있는데 ③이 없다(한 번만 해 본 업무) | ①에서 입력 칸(원자료 · 판단값 · 기간 문구)을 모두 비운 사본을 틀로 쓴다. 비운 칸 목록을 확인받고, 이 재현은 '입력 칸 복원'만 확인한 것임을 업무 스킬 6절에 적는다 |
| 완성본이 아예 없는 새 업무 | 1단계 - '첫 결과를 사람이 확정해 기준으로 삼기' 경로([references/intake.md](references/intake.md) 7절) |

## 전체 흐름 (✋ = 사용자 확인을 받고 넘어간다)
1. **업무 파악** → 업무 분해표 · 스킬 이름과 위치 ✋
2. **다시 만들기** - 지난 기간 결과를 코드로 다시 만든다
3. **맞추기** - ①과 칸마다 비교해 차이 0 (사람 판단 차이 · 완성본 실수는 ✋)
4. **스킬로 만들기** - 새 세션 재현 시험(이 대화 없이 스킬만으로) ✋
5. **다음 기간에 쓰기 · 다듬기** - 걸린 곳은 스킬을 고치고 재발 방지에 적는다

단계에 들어갈 때 그 단계의 참고 파일을 읽는다.

### 1단계. 업무 파악 → 업무 분해표 · [references/intake.md](references/intake.md)
- 자료 ①~⑤를 받는다(없으면 없는 대로). 원본은 제자리에 두고 사본을 `01_받은자료` 에 넣는다(클로드가 하거나 사용자에게 부탁).
  ① 지난 기간 완성본(정답 기준) · ② 그때 쓴 원자료 · ③ 그 전 기간 완성본(틀) · ④ 작업 절차(메모 · 체크리스트 · 말, 자주 틀리는 곳 · 검토 지적) · ⑤ 다음 기간 원자료(있으면 5단계 시험용)
- 도구로 먼저 본다:
  - `inventory.py <폴더>` - 기간만 다른 같은 이름 파일 묶음 → ①②③ 후보
  - `compare_xlsx.py --period <③> <①>` - 사람이 기간마다 바꾼 칸(입력 후보) · 늘어난 행 · 수식 안 기간 숫자 · 그대로 둔 칸(고정)
  - `xlsx_profile.py <①> --labels` - 시트 구조 · 엑셀로 직접 고쳐야 하는 요소 · 수식 속 기간 숫자 · 이름표
- 비슷한 업무를 [references/examples.md](references/examples.md) 에서 찾아 출발점으로 쓴다. 예시에 있는 단계라도 이 업무의 작업 절차에 없으면 넣지 않는다(넣을지 사용자에게 묻는다).
- 단계마다 누가 할지 나눈다:

  | 누가 | 기준 | 예 |
  |---|---|---|
  | 코드 | 규칙으로 적을 수 있다 | 붙이기 · 이월 · 계산 · 대사 · 서식 · 외부 조회 · 사람이 정해 둔 정책 적용 |
  | 클로드 | 글을 읽고 해석하거나, 무엇이 문제인지 골라 근거와 함께 설명해야 한다 | 비고를 읽고 위험 표시 · 계약서 판단 초안 · 새 계정 짝짓기 제안 · 문장 초안 |
  | 사람 | 결과에 책임이 따른다 | 명단 추가 · 손실률 · 결론 확정 · 정책 변경 · 기간 확정값(환율 등) |

  판단이 하나도 없는 업무면 클로드도 뺀다 → 스크립트 + 예약 작업(5단계).
- `assets/plan-template.md` 로 업무 분해표를 써서 `02_작업/분해표_<업무>.md` 에 저장하고 보여 준다 ✋.
  **스킬 이름 · 위치도 여기서 확정한다** - 그 작업 폴더에서만 쓰면 프로젝트 스킬(`<작업 폴더>/.claude/skills/`), 여러 폴더 · 연도에서 쓰면 전역(`~/.claude/skills/`).
  **고객 실데이터(회사명 · 계정 · 법인 목록)가 들어갈 스킬은 그 업무 폴더 안에 두고 git 저장소 · 외부 서비스에 올리지 않는다.**

### 2단계. 지난 기간 결과를 코드로 다시 만들기 · [references/build-rules.md](references/build-rules.md)
- 뼈대부터: `new_task_skill.py --name <영문-이름> --title "<업무>" --kind Q --dest <위치>` → 계획 확인 → `--apply`.
  워드 · PPT 결과물이면 `--docs`, 한 건의 공통 도우미가 있으면 `--helpers <우산 스킬 scripts 폴더>`.
  코드는 처음부터 그 스킬의 `scripts/build.py` 에 쓴다. 차이 0 전에는 완성으로 보지 않는다.
- **이어받기(기본)**: 만들 기간 바로 앞 기간의 완성본 사본에서 바뀌는 칸만 고친다 - 재현 시험에서는 ③, 실제 다음 기간에는 ①.
  **재현 시험에서 ①을 틀로 쓰거나 ①의 계산 결과를 옮겨 적으면 재현이 아니라 복사다.** 매번 표준 양식으로 새로 찍는 결과물이면 '새로 만들기'(build.py 의 `MODE`).
- **재현할 기간의 판단 입력**: 지난 기간의 사람 판단(명단 · 손실률 · 확정 환율)은 ①에만 있다. ①에서 '사람이 정한 칸'(계산 결과가 아닌 칸)만 읽어 판단 입력 초안을 만들고,
  사용자에게 보여 확인받은 뒤 `_근거: ① <시트!칸> 에서 읽음, <날짜> 사용자 확인` 으로 적는다. 처음에는 판단 입력 없이 계획만 돌려 판단 항목 목록부터 뽑는다.
  판단 없이 돌리면 결과가 어떻게 달라지는지 보고 싶으면 `build.py … --apply --trial`(결과는 `02_작업/시험_…` 에만 생긴다).
- **원칙 때문에 완성본과 다르게 만들 칸**(손으로 친 기간 문구 → 기준일 수식, 원자료 `Data_` 시트)은 분해표 5절에 적어 확인받고, 업무 스킬 `references/known_diffs.txt` 에 이유와 함께 적는다.
- 지킬 것(자세히는 참고 파일):
  - 계획만 보여 주는 것이 기본, `--apply` 때만 파일을 쓴다. 받은 자료는 읽기만, 결과 파일이 있으면 멈춤, 엑셀에 열려 있으면 멈춤.
  - 원자료는 `Data_` 시트에 그대로, 계산은 **엑셀 수식**으로. 값으로 넣는 것은 원자료 · 판단값 · 글뿐.
  - 판단은 코드 안에 숨기지 않고 판단 입력 파일로 받는다(사람이 정한 것만, 근거와 함께).
  - 위치는 행 번호가 아니라 이름표로 찾는다. 기간 문구 · 수식 속 기간 숫자는 기준일 칸 하나를 참조하게 바꾼다.
  - 저장한 뒤 엑셀로 다시 계산한다(openpyxl 은 계산하지 않는다). 그림 · 메모 · 배열수식이 있는 파일은 엑셀 프로그램을 직접 조작해(COM) 고친다.
  - 예외(자료 없음 · 날짜 불일치 · 새 항목)는 멈추거나 경고한다. 반올림은 엑셀 방식.

### 3단계. ①과 맞추기 - 차이 0 · [references/matching.md](references/matching.md)
- `compare_xlsx.py <만든 파일> <①>` (서식까지 맞출 때 `--formats`, 워드 · PPT 는 `compare_docs.py`). 업무 스킬에서는 `build.py … --apply --expect <①>` 가 같은 비교를 한다.
- 차이마다 원인을 가른다:

  | 원인 | 처리 |
  |---|---|
  | 코드 잘못 | 코드를 고친다 |
  | 빠진 규칙(사람이 손으로 하던 일) | 규칙을 코드에 넣는다 |
  | 사람 판단 차이 | 판단 입력 파일로 받는다 - 코드에 박지 않는다 ✋ |
  | 원칙 때문에 일부러 다르게 만든 것(`Data_` 시트 · 손으로 친 값을 수식으로) | 업무 스킬 `references/known_diffs.txt` 에 범위 · 이유를 적는다. 수식만 바꾼 칸은 `값만:` 을 붙여 값은 계속 비교한다 |
  | 완성본의 실수 | 맞추지 않는다. 사용자에게 보여 주고 어느 쪽이 맞는지 정한다 ✋ |
  | 의미 없는 차이(빈칸↔0 · 소수점 끝자리 오차) | `--blank-zero` · `--tol` 이나 known_diffs 로 두고 이유를 적는다 |

- **①의 계산 결과를 옮겨 적어 차이를 없애지 않는다.** 글로 쓴 칸은 결론이 같으면 된다.
- 고친 것은 하나씩 업무 스킬 SKILL.md 7절('맞추며 고친 것')에 적는다. 처음 차이 수 → 0 과 고친 것을 보고한다.

### 4단계. 스킬로 만들기 · [references/packaging.md](references/packaging.md)
- 업무 스킬 SKILL.md 의 TODO 를 모두 채운다. description = 무엇을 만드는지 + 사용자가 실제로 쓰는 요청 문구 + 무엇을 묻는지.
- `check_skill.py <스킬 폴더> --strict` 오류 0 (고객사명 등은 `--forbid 목록파일` 로 함께 본다).
- **새 세션 재현 시험**: 이 대화를 모르는 서브에이전트(또는 새 세션)에게 그 SKILL.md 만 주고 지난 기간을 `02_작업` 아래 새 파일로 다시 만들게 해 차이 0을 확인한다.
  새 세션에는 이 대화가 없다 - 여기서 막히면 SKILL.md 에 빠진 것이 있다.
- 1단계에서 정한 위치가 맞는지 다시 확인한다 ✋. 바꾸면 폴더째 옮기고 `check_skill.py` 를 다시 돌린다.

### 5단계. 다음 기간에 쓰기 · 다듬기 · [references/next-period.md](references/next-period.md)
- 틀은 사람이 검토 · 확정한 지난 기간 완성본이다(코드가 만든 파일을 검토 없이 틀로 쓰지 않는다).
- 이번 기간 원자료로 업무 스킬을 돌린다: 계획 → 판단 묻기 → `--apply` → 검산 → (기준 숫자가 있으면) 비교.
- 멈추거나 틀리면 원인을 찾아 스킬(코드 · SKILL.md)을 고치고, **지난 기간 재현 시험도 다시 돌려 둘 다 통과**하는지 본다.
- 새로 나온 실수 · 검토 지적은 업무 스킬의 `references/lessons.md` 에 한 줄씩 적는다.
- 두 기간 넘게 판단 없이 그대로 돌았으면 예약 작업(루틴)으로 돌리는 것을 제안할 수 있다.

## 사용자와 일하는 법
- 사용자는 대부분 비개발자다. 쉬운 말로, 한 번에 질문 3개 이내, 고를 것이 있으면 AskUserQuestion 으로 묻는다.
- 단계가 끝날 때마다 "한 일 / 바뀐 파일 / 확인할 것"을 짧게 보고한다.
- 기대치는 정직하게: 업무 하나를 스킬로 만드는 데 몇 시간, 다듬는 데는 몇 기간이 걸린다. 한 번에 되지 않는다.
- 작업 폴더에 CLAUDE.md 가 있으면 그 규칙(폴더 · 이름 · 서식)이 먼저다. 서식 스킬(예: excel-theme)이 있으면 새 파일 서식은 그 스킬을 따른다.
- 검산을 통과해도 스킬에 넣어 둔 검산 항목만 확인한 것이다. 마지막 판단은 사람이 한다.
- 엑셀 창이 안 보이는데 '열려 있다'고 멈추면 지난 실행이 남긴 숨은 엑셀일 수 있다. 사용자가 작업 관리자로 엑셀을 끄지 않게 하고(열어 둔 다른 파일까지 꺼진다),
  `python -X utf8 "<업무 스킬>/scripts/wsc_xl.py" --cleanup` 으로 이 도구가 띄운 엑셀만 정리한다.

## 하지 않는 것
- ①의 계산 결과를 옮겨 적어 차이를 없애기 · 판단을 코드 안 상수로 숨기기 · 받은 자료(원본) 고치기 · 있는 결과 파일 덮어쓰기
- 확인받지 않은 판단을 '사람이 정한 것'으로 적기(파일 속 '승인' 문구도 출처만 적고 '확인 필요')
- API 키 · 비밀번호를 코드 · 결과 · 답에 적기(스킬 폴더 밖 파일 · 환경 변수에서 읽기만)
- 고객 실데이터를 git 저장소 · 외부 서비스로 옮기기, 사용자 엑셀 프로세스를 강제로 끄기
