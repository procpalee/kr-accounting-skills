# 2단계 - 코드 원칙과 함정

업무 스킬의 `scripts/build.py` 를 쓸 때 지킨다. 뼈대(`new_task_skill.py`)가 이 원칙대로 되어 있으니 TODO 만 채우면 대부분 지켜진다.
공용 도우미는 업무 스킬의 `scripts/wsc_xl.py` 에 복사되어 있다(아래 `W.` 로 표기).

## 1. 이어받기 vs 새로 만들기 (build.py 의 `MODE`)

| | 이어받기(기본) | 새로 만들기 |
|---|---|---|
| 방법 | 만들 기간 바로 앞 기간 완성본의 사본에서 바뀌는 칸만 고친다(재현 시험에서는 ③, 실제 다음 기간에는 ①) | 원자료 + 양식(`FORM`)에서 매번 새로 만든다 |
| 맞는 경우 | 회사 · 사람이 만든 양식, 서식 · 메모 · 구조가 복잡한 결산파일 | 표준 양식 보고서 · 집계표, 지난 파일 구조가 매번 흔들릴 때 |
| 장점 | 서식 · 구조가 사람 것 그대로 - 맞추기가 빠르다 | 지난 기간의 실수 · 잔재가 따라오지 않는다 |
| 주의 | **지난 기간 값이 남는 칸**(키인 값 · 기간 문구 · 지난 표시 색)을 모두 찾아 비운다 | 서식을 코드가 다시 칠해야 한다(서식 스킬이 있으면 그것을 쓴다) |

재현 시험에서 ①(정답 기준)을 틀로 쓰면 아무것도 확인한 것이 아니다.

## 2. 파일 안전

- 받은 자료(원본)는 읽기만 한다. 가공이 필요하면 `02_작업` 에 사본을 만든다. 도우미는 `01_받은자료` 아래 파일을 제자리에서 고치려 하면 멈춘다(`W.guard_not_received`).
- 결과는 새 파일로 만든다. 이미 있으면 멈춘다 - 사람이 손댄 파일일 수 있다.
  뼈대는 `<결과>.작업중.xlsx` 에 만들고, 다시 계산 · 검산이 끝난 뒤에만 결과 이름으로 바꾼다. 중간에 실패하면 작업중 파일을 지운다(반쪽 파일이 다음 기간 틀로 잡히지 않게).
  검산이 안 맞으면 결과 이름 끝에 `_확인필요` 를 붙여 통과한 파일과 구별한다.
- 재현 시험 결과(`02_작업/재현_<기간>…`)는 코드가 만든 시험 파일이라 지워도 된다. 같은 이름이 있으면 뼈대가 이름 끝에 시각을 붙인다.
- 틀(지난 완성본)은 계획에 후보를 모두 보여 준다. 후보가 여럿이거나 코드가 만든 파일(`03_산출`)뿐이면 멈추고, 사람이 확정한 파일을 `--prior` 로 받는다.
- 쓰기 전에 엑셀에 열려 있는지(`~$` 잠금 파일) 본다 - 뼈대는 계획 단계에서 틀 · 원자료 · 결과를 모두 본다.
- 기본 실행은 **계획만** 보여 준다. `--apply` 를 줘야 쓴다. 계획에는 쓸 파일 · 판단 입력 요약 · 판단할 것 · 멈춤 · 경고를 모두 보여 준다.

## 3. 엑셀 원칙

- **계산은 엑셀 수식으로 남긴다.** 파이썬으로 계산한 값을 넣지 않는다 - 검토자가 수식을 따라갈 수 있어야 하고, 판단값이 바뀌면 자동으로 다시 계산되어야 한다.
- 값으로 넣는 것은 원자료 · 판단값 · 글뿐이다. 원자료는 `Data_<이름>` 시트에 받은 그대로 붙이고(손으로 옮겨 적지 않는다), 계산 시트는 그 시트를 참조한다.
- 받는 사람이 보면 안 되는 열(주민번호 · 개인별 급여 · 내부 메모)은 `Data_` 시트에 넣기 전에 빼고, 뺀 것을 업무 스킬 8절(한계)에 적는다.
- 원자료가 PDF · 스캔 · 메일이면(계약서 등) `Data_` 시트 대신, 읽어 낸 값(개시일 · 기간 · 금액)을 **판단 입력**이나 명세 시트 한 줄로 받고
  어느 쪽 · 어느 조항에서 읽었는지 근거를 함께 적는다. 숫자를 읽어 낸 것은 클로드의 일이므로 사용자 확인을 받는다.
- 값만 받는 결과물(ERP 전표 업로드 · CSV · 제출 양식)은 작업 파일(수식)과 제출 파일(값)을 나눠 만들고, 제출 파일은 작업 파일의 계산값을 그대로 내보낸다.
- 지난 기간 결과(기초 이월)는 틀의 **계산값**을 읽어 넣는다(`W.cached_values` - 비어 있으면 임시 사본을 다시 계산해 읽는다).
- 저장한 뒤 **엑셀로 다시 계산해 저장한다**(`W.excel_recalc`). openpyxl 은 수식을 계산하지 않아서, 다시 계산하지 않으면 계산값이 빈 파일이 된다.
- 새 엑셀 파일 · 새 시트의 서식은 작업 폴더의 규칙이나 서식 스킬(있으면)을 따른다. 이어받기면 지난 파일 서식을 그대로 쓴다.

## 4. 판단 입력 파일

사람이 정한 것을 코드에 전하는 통로다. 기간마다 `02_작업/판단입력_<기간>.json`.

```json
{
  "_근거": "2026-10-13 사용자 답(채팅). 명세서 비고의 '팀장 승인' 문구는 출처로만 적음 - 승인 사실 확인 필요",
  "기간": "2026-06",
  "판단확인": true,
  "개별평가_추가": [{"거래처명": "거래처 A", "구분": "개별(부도)", "손실률": 1, "앞에": "거래처 B"}],
  "손실률_변경": []
}
```

- 사람이 정한 것만 적는다. 클로드가 먼저 정해 넣지 않는다. 기본값이 필요하면 "지난 기간과 같게"를 사용자에게 확인받고 적는다.
- `_근거` 에 누가 · 언제 · 어떻게 정했는지 적는다. 파일 속 '승인' 문구는 클로드가 사실을 확인할 수 없으므로 출처만 적고 '확인 필요'로 보고한다.
- **재현할 기간의 판단**은 ①에서 '사람이 정한 칸'(명단 · 손실률 · 확정 환율 - 계산 결과가 아닌 칸)만 읽어 초안을 만들고, 사용자 확인을 받은 뒤 `_근거` 에 "① <시트!칸> 에서 읽음, <날짜> 사용자 확인"으로 적는다.
- 뼈대는 `기간` 이 `--period` 와 다르면 멈추고(지난 기간 판단이 그대로 쓰이지 않게), `판단확인` 이 참일 때만 `--apply` 를 진행한다.
  다만 `판단확인` 도 클로드가 적는 글자다 - 코드가 사람 확인을 보장하지는 않는다. **사용자 답을 받은 뒤에만 true 로 적는다**는 약속이다.
- 판단이 없는 업무면 build.py 의 `NEEDS_JUDGMENT = False` - 판단 입력 파일 없이 돈다(예약 작업용).
- 판단 결과를 결과 파일 안에도 남기고 싶으면 '판단근거' 시트(판단 · 근거 · 결론 · 출처)를 둔다.

## 5. 위치 찾기와 행 수 변화

- 행 번호를 코드에 박지 않는다. 다음 기간에 명세 · 명단 행 수가 바뀌면 틀린 칸을 읽고 쓴다.
  이름표('합계' · '1. 차입금' · '구분')로 찾는다(`W.find_label`). 이름표 목록은 `xlsx_profile.py --labels` 로 본다.
- 행을 늘리고 줄일 때:
  - openpyxl 은 행을 넣어도 **다른 칸의 수식 참조를 옮겨 주지 않는다** → 관련 수식 범위(SUMIFS 범위 · 합계 행 참조)를 코드가 다시 쓴다.
  - 조건부 서식 · 데이터 유효성(드롭다운) · 이름 정의(인쇄 영역) · 병합 · 차트 범위도 옮겨 주지 않는다 → 늘린 행까지 덮는지 확인한다.
  - 참조가 여러 시트에 얽혀 있으면 엑셀을 직접 조작해(`W.ExcelEdit` 안에서 `ws.Rows(n).Insert()`) 행을 넣는다 - 엑셀이 참조를 옮겨 준다.
    `W.find_label` 은 openpyxl 시트용이므로, 위치는 openpyxl 로 먼저 찾고 행 삽입은 그다음 `ExcelEdit` 로 한다.
- 서식은 같은 종류의 이웃 행에서 복사한다. 마지막 행 · 합계 행 서식(굵은 선)이 한 칸 위로 붙지 않게 주의한다.
- 사람은 시트마다 행을 늘리는 방식이 다를 수 있다(합계 아래 빈 줄을 먼저 씀 / 행을 끼워 넣음). `compare_xlsx --period` 의 시트별 '늘어난 행' · '밀린 행'으로 확인하고,
  한 기간만 보고 정한 규칙이면 업무 스킬 8절에 그렇게 적는다(다음 기간에 다르면 멈추게).
- 지난 기간 표시(노란 칸 · 메모)는 이번 기간 기준으로 지우고 다시 칠한다.

## 6. 기간 처리

- `W.Period('2026-09', 'Q')` - 기준일(`.end`) · 직전 기간(`.prev()`) · 분기 번호(`.q`) · 표기(`.ym` `.dot` `.yq` `.fy` `.kor`).
  회계연도가 12월에 끝나지 않으면 `W.Period('2026-09', 'Q', fy_end=3)`(분기 번호 · 연초 판단이 회계연도 기준).
- 파일 이름 규칙에는 `{ym}` `{dot}` `{yq}` `{fy}` `{q}` `{year}` `{mm}` 과 `*` 를 쓸 수 있다(뼈대의 `PRIOR_NAME` 등).
- 기준일은 **한 칸**에만 넣고, 적요 · 머리글 · 기간 문구는 그 칸을 참조하는 수식으로 둔다(예: `=YEAR($C$2)&"."&ROUNDUP(MONTH($C$2)/3,0)&"Q"`).
  수식 안에 박힌 기간 숫자(`202606` · `">=202604"` · `DATE(2026,6,30)`)도 그 칸을 참조하게 바꾼다 - 손으로 고치던 칸이 남으면 다음 기간에 지난 숫자가 그대로 나간다.
  계약 개시일처럼 기간과 상관없는 고정 날짜는 그대로 둔다(`compare_xlsx --period` 에서 실제로 바뀐 것만 고른다).
- 양식에 기준일 칸이 없으면 새로 둔다: 사람이 만든 표 · 인쇄 범위를 건드리지 않는 머리 부분(제목 옆 빈 칸)에, 엑셀 **날짜**로.
  기존 수식이 `202606` 같은 년월 숫자로 비교하면 옆에 `=YEAR(기준일)*100+MONTH(기준일)` 보조 칸을 두고 그것을 참조한다.
  새로 둔 칸은 분해표 5절에 적어 확인받고 known_diffs 에 넣는다.
- 기준일이 월말이 아닌 수시 업무는 `--asof YYYY-MM-DD` 로 기준일을 준다.
- 연초 첫 기간(1월 · 1분기)은 이월 기준이 다를 수 있다(전기말 잔액에서 시작, 연간 갱신 자료). 확실하지 않으면 그 기간에는 멈추고 묻는다(`period.is_year_start`).
- 분기 비율처럼 기간에 따라 바뀌는 계수는 기간에서 계산한다(예: 남은 분기 비율 `(4-q)/4`). 사람이 매번 손으로 바꾸던 칸이면 특히.

## 7. 공유 확정값 (여러 업무가 같은 값을 쓸 때)

기말 환율 · 기준 금리처럼 여러 업무가 같이 쓰는 기간 값은 **기간마다 한 번 확정해 한 파일에 둔다**.
```python
v = W.shared_value(확정값_파일, "USD")                          # 없으면 None
W.shared_value(확정값_파일, "USD", 1541.5, source="예금 명세 환율 열")  # 확정 · 저장(사용자 확인 뒤)
```
- 코드가 자료에서 후보를 찾아(근거 파일 이름과 함께) 보여 주고 → 사용자가 확정 → 저장. 모든 업무 스킬은 그 파일을 읽는다.
- 이미 확정된 값과 다른 값을 저장하려 하면 멈춘다(바꾸려면 `force=True`, 명령 옵션은 `--force-<무엇>`). 지난 기간 값이 남아 잘못 쓰이는 실수를 막는다.

## 8. 예외 - 멈춤과 경고

- 멈춤: 결과를 만들면 안 되는 상황(자료 없음 · 기준일 불일치 · 지난 기간에 없던 구조 · 판단 미정 · 판단 입력 기간 불일치).
- 경고: 만들되 사람이 꼭 봐야 하는 것(1년 이내 만기 · 검산 불일치 · 큰 증감 · 외부 연결).
- 멈춤 메시지는 **무엇이 · 왜 · 어떻게 하면 되는지** 한 줄로. 예: `[멈춤] 평가일(2026-09-29) ≠ 결산일(2026-09-30) - 결산일 기준 평가표를 받거나 --force-date`.
- 대사가 안 맞을 때 차이를 억지로 맞추지 않는다. '확인 필요(Pending)'로 결과에 보이게 남긴다.

## 9. 엑셀 · 문서 함정 (실제로 겪은 것)

| 함정 | 대처 |
|---|---|
| openpyxl 로 저장한 파일은 계산값이 비어 있다 | 저장 후 `W.excel_recalc`, 읽을 때 `W.cached_values` |
| 그림 · 도형 · 스레드 메모 · 슬라이서 · 웹 추가기능 · 유효성 확장이 있는 파일을 openpyxl 로 저장하면 사라지거나 엑셀이 못 연다 | `xlsx_profile.py` 로 먼저 보고, 있으면 `W.ExcelEdit` 로 고친다 |
| `.xlsm` 을 openpyxl 로 열고 저장하면 매크로가 사라진다 | `load_workbook(…, keep_vba=True)` 로 열고 `.xlsm` 으로 저장 |
| 엑셀은 상대 경로를 못 찾는다(재계산이 조용히 빠져 계산값이 빔) | 항상 절대 경로(`Path.resolve()`) |
| 엑셀은 전체 경로가 218자를 넘는 파일을 못 연다 | 작업 폴더를 얕게 두거나 이름을 줄인다 |
| 사용자가 열어 둔 엑셀에 붙으면 그 창을 닫아 버릴 수 있다 | 새 인스턴스(`DispatchEx`)만 쓰고 그것만 끈다(도우미가 그렇게 한다) |
| 실패 · 시간 초과로 숨은 엑셀이 남아 `~$` 잠금을 쥔다 | 도우미가 띄운 엑셀만 기록해 두고 `wsc_xl.py --cleanup` 으로 그것만 정리. 작업 관리자로 엑셀을 통째로 끄지 않는다 |
| 엑셀 재계산은 외부 연결을 새로 고치지 않는다(지난 기간 연결 값이 남음) | `xlsx_profile.py` 가 외부 연결을 알려 주면 계획에서 경고하고, 연결 대상이 이번 기간 파일인지 확인 |
| TODAY() · NOW() 같은 휘발성 함수는 재현할 때마다 값이 바뀐다 | 기준일 칸으로 바꾸거나 known_diffs 에 적는다 |
| 파이썬 `round` 는 0.5 를 짝수 쪽으로 보내 1원씩 어긋난다 | `W.round_half_up`(엑셀 ROUND 와 같음) |
| `freeze_panes = None` 만 하면 선택 영역이 남아 엑셀이 파일을 못 연다 | `ws.sheet_view.pane = None` + 선택 영역 초기화까지 |
| 엑셀이 저장한 자동 행 높이를 openpyxl 로 다시 저장하면 고정 높이로 굳고, `copy_worksheet` · `insert_rows` 뒤에는 엉뚱한 행에 붙는다(openpyxl 은 높이 값만 있으면 '고정'으로 본다) | 사람이 고정한 높이가 없으면 저장 전에 `W.clear_row_heights(ws)`. `compare_xlsx --formats` 가 파일 원문의 고정 표시(customHeight)로 차이를 잡는다 |
| 채우기 색을 새로 칠하면 배경색(bgColor) 속성이 엑셀 기본값과 달라 서식 비교에서 다르게 보일 수 있다 | 같은 종류 칸의 채우기를 복사해 쓰거나, 배경색을 엑셀 기본(indexed 64)으로 둔다 |
| 더존 등에서 받은 `.xls`(옛 형식)는 openpyxl 이 못 읽는다 | `W.xls_to_xlsx(원본, 02_작업)` - 임시 사본을 엑셀로 열어 `.xlsx` 로 저장(원본은 그대로) |
| ERP 보고서의 제목 · 머리글 줄을 계정 줄로 읽는다 | 머리글 이름표로 표 시작을 찾고, 숫자 칸이 비거나 글자인 줄은 건너뛴다 |
| 반올림 잔여(1원 · 28원)가 끝난 계약 · 행에 남는다 | 마지막 회차가 잔여를 정리하게 하거나, 원자료의 흠으로 보고한다 |
| 한글 윈도우 출력이 깨진다 | `python -X utf8`, 다른 프로그램 출력(`tasklist` 등)은 cp949 로 읽는다. 메모장으로 저장한 JSON 은 `utf-8-sig` 로 읽는다 |
| PPT 에 그림을 상대 경로로 저장하지 못한다 | 절대 경로, 원본 파일은 임시 폴더 사본으로 연다(잠금 파일이 받은 자료 폴더에 생기지 않게) |
| CSV 한글이 깨진다 | `utf-8-sig` → 안 되면 `cp949` 로 읽는다 |
| 윈도우 작업 스케줄러로 엑셀 자동화를 돌리면 로그온하지 않은 상태에서 실패한다 | '사용자가 로그온할 때만 실행'으로 둔다 |

## 10. 워드 · PPT 결과물

- 양식은 코드로 고정하고 내용만 클로드가 쓴다. 양식의 칸은 레이아웃에 붙은 이름(구분 · 제목 · 요지 …)으로 찾는다.
- 숫자는 코드가 원자료(정산표)에서 읽어 문구 양식의 빈칸을 채운다. 방향 말('늘었다/줄었다')도 숫자 부호로 코드가 정한다.
- **승인 관문**: 쪽별 제목 · 핵심 메시지 목록을 `02_작업/제목목록_<기간>.json` 으로 보여 주고, 승인받으면 그 파일에 `"승인": true, "승인일"` 을 적는다.
  build 는 승인이 없거나 승인 뒤 목록 내용이 바뀌었으면(내용 해시 비교) 만들지 않는다.
- 만든 뒤 쪽마다 그림으로 내보내 넘침 · 겹침을 눈으로 본다. 재현 비교는 `compare_docs.py`(뼈대의 `--expect` 가 확장자를 보고 고른다).

## 11. 스크립트 모양

- 실행 예를 맨 위 설명에 한 줄씩 적는다(계획 · 만들기 · 재현 시험).
- 옵션(뼈대와 같게): `--period` · `--asof` · `--root` · `--prior` · `--raw 키=경로`(여러 번) · `--judgment` · `--out` · `--apply` · `--expect` · `--formats` · `--cmp "<비교 도구 추가 옵션>"`.
- 출력은 한국어로 짧게: `[계획]` · `[판단 필요]` · `[경고]` · `[멈춤]` · `✓/✗ 검산`. 종료 코드: 정상 0 · 멈춤 · 불일치 1.
- 검산(`verify()`)이 하나도 없으면 뼈대가 경고하고 1 을 돌려준다 - 검산 없는 업무 스킬은 넘기지 않는다.
- 키 · 비밀번호는 스킬 폴더 밖 파일이나 환경 변수에서 읽고, 코드 · 출력 · 결과 파일에 적지 않는다.
