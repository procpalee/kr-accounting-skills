# 업무별 나누기 예

새 업무를 나눌 때 비슷한 예를 찾아 출발점으로 쓴다. 회사 · 사람 이름은 가상이거나 뺐다.
각 예의 표 = 코드가 할 일 / 클로드가 할 일 / 사람이 정할 일, 그리고 멈춤과 검증.
**예시는 다른 회사의 방식이다.** 예시에 있는 단계(외부 조회 · 특정 시트 · 정책)라도 이번 업무의 작업 절차에 없으면 넣지 않고, 넣을지 사용자에게 묻는다.

## 1. 대손충당금 분기 결산파일

결과물: 충당금계산 · 연령분석 · 설정정책 · 채권명세_<기간> 시트. 입력: 지난 분기 결산파일 + 이번 분기 채권명세서.

| 누가 | 할 일 |
|---|---|
| 코드 | 명세서를 `채권명세_<기간>` 시트로 붙이고 연령분석 행 수 · 수식 범위를 늘리고 줄인다 / 경과개월 · 구간 배분 · 집합 · 개별 충당금 · 추가전입(환입) · 결산분개 · 대사를 수식으로 / 기준일 · 전분기말 잔액(지난 파일 계산값) 이월 / 국세청 휴폐업 조회 → 폐업이면 정책대로 개별(폐업) 100% |
| 클로드 | 비고 칸("어음 부도" · "회생" · "결제 연장")을 읽고 명단 밖 위험 거래처를 표시 · 보고 / 휴업 거래처를 골라 설명 |
| 사람 | 개별평가 명단 추가 · 구분 · 손실률, 휴업 거래처 처리, '폐업 100%' 같은 정책 자체 |

- 판단 입력: `개별평가_추가[{거래처명, 구분, 손실률, 앞에}]` · `손실률_변경` · `표시만`(위험 표시는 하되 명단에 넣지 않기로 한 거래처).
- 멈춤: 지난 파일에 계산값이 없음(엑셀로 한 번 열어 저장 필요) · 결과 파일이 있음 · 파일이 열려 있음.
- 검증: 결산분개 대차 일치 · 대사 OK · 연령분석 검증 열 OK / 재현: 지난 분기 완성본과 칸 비교 차이 0.
- 이런 업무에서 흔히 걸리는 것: 명단이 한 줄 늘면 아래 칸이 모두 밀림(사람 판단 하나가 수백 칸 차이로 보임) · 지난 분기 표시 색이 따라옴 · 마지막 행 테두리 · 코드 열의 앞자리 0 · 엑셀 자동 행 높이가 고정으로 굳음.

## 2. 리스 결산파일 (새 계약 판단 포함)

결과물: 분기말잔액 · 결산분개 · 판단근거 · 상각표 · 증분차입이자율 · 계약명세. 입력: 지난 분기 결산파일 + 새 계약서 PDF.

| 누가 | 할 일 |
|---|---|
| 코드 | 계약별 상각표(현재가치 · 이자 · 지급) · 분기말 잔액 · 결산분개 · 잔액 증감 검산(기초 + 신규 + 이자 - 지급 = 기말) / 판단 입력의 계약 조건으로 새 계약 행 추가 |
| 클로드 | 새 계약서를 읽고 리스인지 · 비리스요소(정비료 등)를 나눌지 · 리스기간 판단 초안을 기준서 문단 근거와 함께 '판단근거' 시트에 / 계약서 조건(개시일 · 기간 · 리스료) 판독 |
| 사람 | 판단 초안 확인 · 결론 확정(확정 전에는 결과 파일을 만들지 않는다) / 해지 · 변경 여부 |

- 멈춤: 판단 확인 전 · 계약서에서 조건을 못 읽음 · 지난 분기에 없던 계약 유형.
- 검증: 잔액 증감 검산 · 상각표 마지막 회차 잔액 0. 글 칸(판단근거)은 결론이 같으면 된다.
- 흔한 걸림: 반올림 잔여 1원 · 28원이 끝난 계약에 남음 → 마지막 회차가 잔여를 정리.

## 3. 분기 정산표 (ERP 자료 + 결산파일 → 재무제표)

결과물: 계정표 · 수정분개(AJE) · 시산표(TB) · BS · IS · 공시용 · 주석 · `Data_ERP`. 입력: 지난 분기 정산표 + ERP 재무상태표 · 손익계산서 + 그 분기 결산파일(대손 · 리스).

| 누가 | 할 일 |
|---|---|
| 코드 | ERP 보고서를 `Data_` 시트로(제목 줄 건너뛰기) · 누계에서 분기 금액 계산 · 결산파일에서 수정분개 금액 읽기(손으로 옮겨 적지 않음) · BS · IS · CE 검증 수식 · ERP ↔ 결산파일 대사 |
| 클로드 | ERP 에 새 계정이 생기면 계정표 짝짓기 안을 낸다 / 대사가 안 맞을 때 원인 후보를 찾는다 |
| 사람 | 새 계정 짝 확정(확정한 짝은 계정표에 추가해 다음부터 코드가 적용) · 대사 차이 처리 |

- 멈춤: ERP 와 결산파일이 1원이라도 안 맞으면 정산표를 만들기 전에 멈추고 묻는다(덕분에 원자료의 반올림 흠을 찾음).
- 검증: BS · IS · CE 검증 0 · 분기순이익 · 자산총계.

## 4. 분기 결산 보고 PPT

결과물: 9쪽 보고서(표지 · 요약 · 손익 · 재무상태 · 확인 사항). 입력: 그 분기 정산표 + 지난 분기 보고서 + 양식.

| 누가 | 할 일 |
|---|---|
| 코드 | 정산표 숫자 읽기 · 억원 변환 · 반올림(5 이상 올림) · 괄호 표기 · 표 4개 · 차트 3개 · 늘었다/줄었다 같은 방향 말 · 기간 글자 · 검산(자산 = 부채 + 자본 등) |
| 클로드 | 문구 초안(핵심 요약 · 시사점), 증감이 큰 계정 후보, 지난 분기 확인 사항 이어가기 안 |
| 사람 | 확인 사항 목록 · 언급할 계정 · 문장 속 주장이 이번에도 맞는지 · **쪽별 제목 목록 승인**(승인 코드 없이는 PPT 를 만들지 않음) |

- 입력 점검: 지난 보고서 '수정후' 숫자 = 이번 정산표 '전분기' 열(소급 수정 확인).
- 검증: 쪽마다 글자 · 숫자 · 표 · 차트 비교(재현 0곳) + 그림으로 내보내 넘침 · 겹침 확인.
- 흔한 걸림: 지난 분기 문장을 복사해 방향 말('증가')이 틀림 → 방향 말은 코드가 숫자로 정한다.

## 5. 회계 검토보고서(워드)

결과물: 질의 → 사실관계 · 쟁점 · 기준서 근거 · 결론 · 회신 메일. 입력: 질의 메일 + 지난 검토보고서(양식 · 문체 예).

| 누가 | 할 일 |
|---|---|
| 코드 | 양식 채우기(제목 · 날짜 · 표 · 인용 표) · 인용 문단 목록 정리 · 숫자 표 계산 |
| 클로드 | 기준서 · 질의회신을 찾아 근거 문단과 결론 초안 / 인용 원문 일치 확인 |
| 사람 | 결론 확정 · 회사에 보낼지 결정(메일은 초안까지) |

- 검증: 검토 에이전트(숫자 대조 · 인용 원문 · 결론과 근거의 연결)를 1~3회 / 글은 결론 · 금액 · 문단 번호가 같으면 된다.

## 6. 외화차입금 환산 · 통화스왑 평가 (실무 사례)

결과물: 차입금 환산 · 파생상품 평가 · 결산분개 · 환원분개 한 시트 + 은행 평가표 `Data_` 시트. 입력: 직전 분기 최종본 + 은행 평가내역서(통화별) + 기말 환율.

| 누가 | 할 일 |
|---|---|
| 코드 | 은행 평가표 시트째 교체 · 평가액 = 은행 순합계 · 유동/비유동 = 결산일 + 12개월 기준 · 분개는 MAX 규칙(자산 ↔ 부채로 부호가 바뀌어도 손으로 다시 연결하지 않음) · 적요는 결산일 수식 · 기초 = 직전 분기말 이월 |
| 클로드 | 기말 환율 후보를 자료(예금 명세 환율 열 · 은행 환율)에서 빈도순으로 근거와 함께 제시 |
| 사람 | 환율 확정(한 번 확정하면 모든 업무가 같이 씀) · 환원분개 처리 방식 |

- 멈춤: 평가표 없음 · 평가일 ≠ 결산일 · 잔여원금 ≠ 명목(일부 상환) · 만기 경과(결제 분개는 스킬 밖) · 새 계약(행 구조가 바뀜).
- 경고: 1년 이내 만기(유동성 대체).
- 재현: 지난 분기 자료로 지난 분기 완성본과 결과 칸 대조(전부 일치).

## 7. 결산보고서(재무제표 + 계정별 명세서) (실무 사례)

| 누가 | 할 일 |
|---|---|
| 코드 | 재무제표 = 정산표(수정후) 수식 · 회사 명세서 시트 교체 · 명세 합계 vs 재무상태표 대사 · 차이를 계정 합계 아래 '정산표 수정분개' 블록으로 보여 줌 · 검증 요약 |
| 클로드 | 설명되지 않는 차이의 원인 후보 |
| 사람 | Pending 처리 결정 |

- 원칙: **수정분개로 설명되지 않는 차이는 맞추지 않고 '확인 필요(Pending)'로 남긴다** - 명세서를 장부에 맞춰서 보내지 않는다.

## 8. 월별 매출 · 핵심 지표 보고 (회계 밖 업무)

결과물: 지난달 대비 · 목표 대비 매출 · 지표 표와 그래프가 든 엑셀 + 한 쪽 요약. 입력: 판매 시스템에서 내려받은 월 매출 명세(CSV) + 목표표 + 지난달 보고 파일.

| 누가 | 할 일 |
|---|---|
| 코드 | CSV 를 `Data_매출_<월>` 시트로 붙이기(인코딩 확인) · 제품 · 지역별 합계 · 지난달 · 작년 같은 달 · 목표 대비 증감률(수식) · 그래프 범위 늘리기 · 원자료 합계 = 시스템 총계 대사 |
| 클로드 | 증감이 큰 항목을 골라 원인 후보를 적은 코멘트 초안(원자료의 거래처 · 제품 단위로 근거를 붙여) |
| 사람 | 코멘트 확정 · 이상치(반품 · 일회성 대량 주문)를 지표에서 뺄지 결정 · 목표 수정 |

- 판단 입력: `제외_거래`(이상치로 뺄 주문번호와 이유), `코멘트_승인`.
- 멈춤: CSV 기준월 ≠ 이번 달 · 새 제품군 · 새 지역(분류표에 없음 → 짝짓기 제안 후 사람 확정).
- 검증: 원자료 합계 = 시스템 총계 · 표 합계 = 원자료 합계 / 재현: 지난달 보고 파일과 칸 비교.

## 9. 공고 수집 · 요약 (예약 작업 사례)

| 누가 | 할 일 |
|---|---|
| 코드 | 조달 API 로 공고 수집 · 키워드로 거르기 · 첨부 내려받기 · 글자 추출 · 이미 처리한 공고 건너뛰기 |
| 클로드 | 공고문을 읽고 참가 자격 · 평가 방식 · 업무량 대비 가격 · 적합성으로 추천 · 검토 · 비추천과 근거 |
| 사람 | 입찰 · 보류 · 제외 결정, 제안서 시작 |

- 매일 아침 예약 작업으로 돈다. 분류 결정과 제안서 초안은 만들지 않게 지시문에 적어 둔다.

## 10. 아침 메일 정리 (예약 작업 사례)

| 누가 | 할 일 |
|---|---|
| 코드(커넥터) | 정해진 시각 이후 받은 메일 읽기 · 첨부를 `받은자료/보낸 곳/날짜/` 에 저장 |
| 클로드 | 회신 필요 · 참고 · 광고 분류, 요청한 사람 · 내용 · 기한 뽑기, 답장 초안 |
| 사람 | 답장 보내기 |

## 11. 판단이 없는 업무 (스크립트만)

예: ERP 계정별원장 여러 시트를 한 시트로 합치고 원장 누계와 대사.
- 전부 코드. 클로드는 처음 만들 때만 쓰고, 이후에는 스크립트 + (필요하면) 예약 작업.
- 검증: 계정별 차변 · 대변 합 = 원장 [누계] 줄(수식으로).
