# 5단계 - 다음 기간에 쓰기 · 다듬기

같은 스킬도 자료가 조금 달라지면 멈춘다. 그때 스킬을 고쳐 나가는 것이 5단계다. 고칠 때마다 그 회사 자료에 맞게 다듬어진다.

## 1. 돌리기

사용자 요청 예: "allowance-quarter 스킬로 3분기(2026-09) 대손 결산 해 줘. 지난 분기: 01_받은자료/…2026-06.xlsx, 이번 채권명세서: …2026-09.xlsx"

1. 업무 스킬의 `references/lessons.md` 를 읽는다(기간 시작 때 볼 항목).
2. **틀 확인**: 지난 기간 결과는 사람이 검토 · 확정한 판이어야 한다. 확정본은 `01_받은자료` 에 정해진 이름으로 두게 하고(또는 `--prior` 로 지정),
   코드가 만든 `03_산출` 파일을 검토 없이 틀로 쓰지 않는다 - 뼈대는 그런 경우 멈춘다.
3. 계획만 돌린다 → 쓸 파일 · 판단 입력 요약 · 판단할 것 · 멈춤 · 경고를 보여 준다.
4. 판단할 것을 묻는다(클로드는 근거 · 후보 · 지난 기간 값을 준비). 답을 이번 기간 판단 입력 파일(`판단입력_<이번 기간>.json`)에 적는다.
   지난 기간 판단 파일을 그대로 쓰지 않는다 - 기간이 다르면 뼈대가 멈춘다.
5. `--apply` → 다시 계산 → 검산 출력.
6. 보고: 핵심 숫자(설정액 · 잔액 · 순이익 등) · 판단한 것 · 경고 · 사용자가 확인할 것.

## 2. 맞는지 보는 법 (다음 기간에는 정답 파일이 없다)

- 내부 검산: 분개 차대 · 명세 합계 = 원자료 합계 · 결과 = 장부(시산표) 대사. 하나라도 안 맞으면 결과 이름에 `_확인필요` 가 붙고, 넘기지 않는다.
- 기준 숫자가 있으면 비교: 회사 장부 · 검토자가 준 숫자 · (강의 · 시험이면) 예시 결과. 여러 파일 값은 `read_values.py` 로 한 번에 읽는다.
- 지난 기간 대비 증감이 큰 항목은 이유를 붙여 보고한다.
- 사람이 결과를 고치면, 고친 칸을 찾아(`compare_xlsx.py` · excel-sync 스킬) 규칙인지 판단인지 가르고 스킬에 반영한다. 고친 판이 다음 기간의 틀(확정본)이다.

## 3. 멈췄을 때

멈추는 것은 고장이 아니다. 사람이 정할 일이 생겼다는 뜻이다. 원인별로:

| 원인 | 처리 |
|---|---|
| 지난 기간에 없던 항목(새 계약 · 새 계정 · 새 거래처 유형) | 사용자와 처리 방법을 정한다 → 규칙이면 코드에, 판단이면 판단 입력 키로 추가 |
| 원자료 형식이 바뀜(열 순서 · 시트 이름 · 머리글) | 코드를 고친다(이름표로 찾게 바꾸면 다음에 덜 깨진다) |
| 원자료 자체가 틀림(합계 불일치 · 다른 기간 자료) | 고치지 말고 사용자에게 알린다 - 회사에 다시 요청할 일 |
| 연초 · 1분기 등 연간 갱신이 필요한 기간 | 갱신 자료를 받아 처리 방법을 정하고 SKILL.md 3절에 적는다 |
| 엑셀 창이 없는데 '열려 있다'고 멈춤 | 지난 실행이 남긴 숨은 엑셀일 수 있다 - `python -X utf8 "<업무 스킬>/scripts/wsc_xl.py" --cleanup`(이 도구가 띄운 엑셀만 정리). 작업 관리자로 엑셀을 통째로 끄지 않는다 |

## 4. 스킬을 고칠 때 - 회귀 확인

스킬(코드 · SKILL.md)을 고쳤으면 **지난 기간 재현 시험을 다시 돌려 둘 다 통과**하는지 본다.
```
python -X utf8 "<업무 스킬>/scripts/build.py" --period <지난 기간> --out 02_작업/재현_<지난 기간>.xlsx --apply --expect "<지난 기간 완성본>"
```
- 이번 기간을 고치다 지난 기간을 깨는 일이 흔하다. 두 기간이 다 맞아야 고친 것이다.
- 재현 시험 결과 이름이 이미 있으면 뼈대가 이름 끝에 시각을 붙인다. `02_작업/재현_*` 은 시험 파일이라 지워도 된다.
- 고친 것은 SKILL.md 7절(맞추며 고친 것)이나 8절(한계)에, 실수 유형은 lessons 에 적는다.

## 5. 재발 방지 (lessons.md)

- 형식: `- [ ] (언제 볼지) 무엇을 확인 - 사례(기간 · 규모 · 출처)`
- 언제 볼지: 기간 시작 때 · 계산 중 · 넘기기 전. 스킬이 기간 시작 때 읽고, 넘기기 전에 다시 훑는다.
- 출처: 검토자 지적 메일 · 사용자가 고친 칸 · 멈춤 사례. 지우지 않고 해결되면 표시만 바꾼다.
- 같은 실수가 두 번 나오면 체크리스트에서 코드(검산 · 멈춤)로 올린다 - 사람이 기억할 일을 줄인다.

## 6. 자동화 단계 올리기

| 단계 | 모습 | 언제 |
|---|---|---|
| 대화 | 매번 말로 시킨다 | 처음 해 볼 때 |
| 스킬 | "○○ 스킬로 해 줘" - 판단은 묻고, 반복은 코드 | 이 스킬로 만든 상태 |
| 스크립트 + 예약 작업 | 정해진 날 저절로 돈다 | 판단할 것이 없어졌을 때(두 기간 넘게 묻지 않고 돌았을 때) - build.py `NEEDS_JUDGMENT = False` |

- 예약 작업: 데스크톱 앱 루틴(로컬 - 앱이 켜져 있고 PC 가 깨어 있을 때만 돈다) 또는 윈도우 작업 스케줄러 + `.bat`('사용자가 로그온할 때만 실행').
  클라우드 루틴은 내 PC 파일을 보지 못한다.
- 판단이 남아 있으면 예약 작업은 '준비까지'(자료 모으기 · 초안 · 보고)만 하고 결정은 사람이 하게 둔다.
- 메일 보내기 · 제출 · 결제처럼 되돌릴 수 없는 일은 예약 작업에 넣지 않는다(초안까지).
