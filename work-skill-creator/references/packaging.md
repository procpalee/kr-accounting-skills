# 4단계 - 스킬로 만들기

목표: 이 대화를 모르는 사람(새 세션)이 업무 스킬만 보고 같은 결과를 낼 수 있게 만든다.
새 세션에는 이 대화가 없다. 대화에서 정한 것 · 맞추며 알게 된 것이 SKILL.md 와 코드에 없으면 다음 기간에 다시 틀린다.

## 1. 업무 스킬 SKILL.md 절별로 쓰는 법

뼈대의 절 순서를 지킨다(점검 도구는 순서는 보지 않고 절 이름이 있는지만 본다).

| 절 | 쓸 것 | 나쁜 예 → 좋은 예 |
|---|---|---|
| 머리 설명 | 실행 한 줄 + "계획 먼저 → 판단 확인 → --apply" + lessons 먼저 읽기 | |
| 1. 입력 | 자료 · 위치 · 이름 규칙 · 쓰는 곳(표) | "채권명세서" → "`01_받은자료/채권명세서_<기간>.xlsx` 시트 1개, B6 머리글, 7행부터, 마지막 '합계' 행 → `채권명세_<기간>` 시트" |
| 2. 코드가 하는 일 | 단계마다 무엇을 · 어디에 · 어떤 규칙으로 | "충당금 계산" → "집합 = 연령 구간별 잔액 × 설정률(SUMIFS 수식), 개별 = 명단 잔액 × 손실률" |
| 3. 기간마다 바뀌는 것 | 기준일 · 이월 · 행 수 · 연초 처리 | |
| 4. 판단 | 판단 · 언제 묻나 · 클로드가 준비할 근거 · 답을 적는 키(표) + 판단 입력 형식 | "명단은 사람이 정함" → "명세서 비고에 부도 · 회생 · 소송 · 결제연장 징후가 있는데 명단에 없으면, 판단 입력 없이 먼저 돌려 위험징후 보고를 보여 주고 거래처별로 넣을지 · 구분 · 손실률을 묻는다 → `개별평가_추가`" |
| 5. 멈춤 · 경고 | 상황 → 처리(표) | |
| 6. 산출 · 검증 | 결과 경로 · 내부 검산 · 재현 시험 명령과 마지막 결과(칸 수 · 날짜) · known_diffs 요약 | |
| 7. 맞추며 고친 것 | 처음 차이 수 → 0, 고친 것 목록(원인 종류) | matching.md 6절 예시 |
| 8. 한계 · 가정 | 전제한 파일 구조, 처리하지 않는 경우, 뺀 개인정보 열 | |

- 왜 그렇게 하는지를 한 줄씩 붙인다("값을 붙여 넣지 않는다 - 판단값이 바뀌면 자동으로 다시 계산되어야 한다"). 이유가 있으면 새 상황에서도 맞게 판단한다.
- 500줄을 넘기지 않는다. 긴 표(계정 매핑 · 법인 목록)는 `references/` 로 빼고 언제 읽는지 적는다.
- 작업 절차 원문은 `references/procedure.md`, 재발 방지는 `references/lessons.md`, 재현 시험에서 뺄 범위는 `references/known_diffs.txt`.
- 여러 사람이 쓰는 스킬(전역 · 배포)이면 7절 · lessons 에 거래처명 대신 '거래처 A', 금액은 규모만 적는다.

## 2. description 쓰는 법

스킬이 불릴지는 description 이 정한다(클로드는 처음에 이름과 설명만 본다).
- **무엇을** 만드는지(입력 → 결과물) + **언제** 쓰는지(사용자가 실제로 쓰는 말 3~5개, 따옴표) + **무엇을 묻는지**.
- 업무 이름을 사용자 말 그대로 넣는다("대손충당금", "대손 결산", "충당금 롤포워드"). 약어 · 영어 이름도 함께.
- 조금 적극적으로 쓴다 - 클로드는 스킬을 덜 부르는 쪽으로 치우친다. 1,024자 이내.
- 예: `대손충당금 분기 결산파일(충당금계산 · 연령분석 · 설정정책 · 채권명세)을 지난 분기 결산파일과 이번 분기 채권명세서로 만든다. "대손충당금 결산", "분기 결산파일 만들어줘", "채권명세서 붙여서 충당금 갱신", "대손충당금 롤포워드" 요청에 쓴다. 개별평가 명단 추가 · 손실률 변경은 사람이 판단하므로 반드시 사용자에게 묻는다.`
- 확실히 부르고 싶으면 작업 폴더 CLAUDE.md 에 한 줄: "대손 결산은 allowance-quarter 스킬로 한다".

## 3. 이름과 위치

- 이름: 영문 소문자 · 숫자 · 하이픈, 64자 이내, 업무가 보이게(`allowance-quarter` · `lease-rollforward` · `quarter-worksheet` · `fx-swap-valuation`).
  `claude` · `anthropic` 은 쓸 수 없다. 한 건 전용 스킬은 건 약칭을 앞에 붙여 묶는다(`<건>-swap` · `<건>-report`).
- 위치:

| 상황 | 위치 |
|---|---|
| 이 작업 폴더에서만, 이 업무 하나만 반복 | 프로젝트 스킬 `<작업 폴더>/.claude/skills/` (또는 스킬 없이 `02_작업` 의 계획 · 코드로 "이 계획과 코드대로 해 줘") |
| 한 폴더에서 여러 업무 | 업무마다 프로젝트 스킬(절차가 섞이지 않는다) |
| 연도별 · 회사별 새 폴더에서 같은 일 | 전역 스킬 `~/.claude/skills/` (고객 고유 정보가 없을 때) |
| 옆 사람에게 넘길 때 | 스킬 폴더째 복사(도우미가 `scripts/` 안에 복사돼 있어 폴더만 있으면 돈다) |
| 회사명 · 계정코드 · 법인 목록 같은 고객 정보가 들어감 | **그 건 폴더의 프로젝트 스킬** - git 저장소 · 외부 서비스에 올리지 않는다 |
| 로직은 여러 회사에 같고 회사별 값만 다름 | 전역 스킬(로직) + 건 폴더 설정 파일(회사별 값) - 스킬은 설정 파일을 읽는다 |
| 한 건에 업무 스킬이 여럿이고 공통 도우미가 있음 | 뼈대를 만들 때 `--helpers <우산 스킬 scripts 폴더>` - 도우미를 복사하지 않고 그 폴더를 불러 쓴다(두 벌이 생기지 않게) |

- 전역 스킬 폴더(`~/.claude/skills`)를 git 으로 관리하고 있다면, 고객 정보 없는 스킬만 거기에 둔다.
- `new_task_skill.py` 는 만들 위치가 git 저장소 안이면 경고한다 - 고객 정보가 들어갈 스킬이면 건 폴더에 만든다.

## 4. 점검

```
python -X utf8 "<스킬>/scripts/check_skill.py" "<업무 스킬 폴더>" --strict [--forbid 금지어.txt]
```
오류 0 이 될 때까지 고친다. 고객사명 등 들어가면 안 되는 단어가 있으면 `--forbid` 목록 파일로 함께 본다.

## 5. 새 세션 재현 시험 - 스킬만으로 재현 (꼭 한다)

이 대화의 기억 없이 SKILL.md 만으로 되는지 확인한다. Agent 도구로 서브에이전트를 띄우거나, 사용자에게 새 세션에서 요청해 달라고 한다.

서브에이전트에게 줄 지시 예:
```
다음 업무 스킬을 읽고 그대로 따라 해라: <업무 스킬 폴더>/SKILL.md
작업 폴더: <작업 폴더>
지난 기간(<기간>) 결산파일을 02_작업/재현검사/ 아래에 새로 만들어라. 판단 입력은 02_작업/판단입력_<기간>.json 을 써라.
만든 뒤 compare_xlsx.py 로 01_받은자료/<완성본> 과 비교해 차이 수를 보고하라.
SKILL.md 만으로 모호했던 곳 · 막힌 곳 · 추측한 곳을 목록으로 보고하라.
```
- 차이 0 이 아니거나 '모호했던 곳'이 나오면 SKILL.md(또는 코드)를 고치고 다시 한다.
  끝내는 기준: 막힌 곳 없이 차이 0 이고, 남은 지적이 문구 수준이면 끝낸다(보통 1~2회). 남긴 지적은 lessons 나 8절에 적는다.
- 서브에이전트가 비교 도구 밖의 차이(창 위치 · 기본 행 높이 · 메모 모양)를 따로 찾아오면: 결과물을 받는 사람에게 보이는 차이면 코드로 고치고 lessons 에 적는다.
  엑셀이 다시 저장하며 생긴 흔적(창 위치 · 시트 선택)이면 SKILL.md 6절에 '비교하지 않는 것'으로 적는다.
- 결과를 SKILL.md 6절에 적는다(예: "새 세션 재현 시험 2026-10-13: 6시트 2,187칸 차이 0").
- 서브에이전트를 띄울 수 없는 환경이면, 이 대화에서 만든 기억을 쓰지 않고 업무 스킬 SKILL.md 만 다시 읽고 그대로 따라 새 경로에 만들어 비교하는 것으로 대신하고, 그렇게 했다고 적는다.

## 6. 검토 에이전트 (판단 · 문장이 많은 결과물)

검토보고서 · 보고서 문장처럼 클로드의 판단이 많이 들어간 결과물은 쓴 클로드와 다른 눈으로 본다.
작업 폴더에 `.claude/agents/<업무>-checker.md` 를 만들어 두고 결과를 만들 때마다 부른다.
- 할 일: 결과의 숫자를 원자료와 대조, 인용 문단이 실제 원문과 같은지, 결론이 근거와 맞는지, 빠진 확인 사항.
- 만든 클로드의 설명은 주지 않고 결과 파일과 원자료만 준다(같은 생각을 따라가지 않게).
- 지적은 '확인 필요' 목록으로 받아 사람이 정한다.
