# 한 건에 반복 업무가 여럿일 때

한 회사의 분기 결산 지원처럼 한 건 안에 결산파일 · 명세서 · 보고서가 여러 개 반복되면, 업무마다 스킬을 하나씩 만들고 그 위에 건 전체를 묶는 **우산 스킬**을 둔다.
이 방식은 실제 분기 결산 지원 용역에서 결산파일 10여 종을 업무별 스킬로 만들면서 정리한 것이다.

## 1. 조사표부터

`assets/survey-template.md` 를 `02_작업/조사표_<건>.md` 로 복사해 채운다. **이 md 파일이 원본이다** - 화면용 HTML 이 필요하면 이 파일에서 만들고, 고칠 때는 md 를 고친다.
- 한눈에 표(순서 · 업무 · 주기 · 의존 · 난이도 · 시간 · 스킬 이름 · 상태) + 업무별 블록(입력 · 코드 · 클로드 · 사람 · 멈춤 · 앞 업무와의 연결).
- 채우는 법: 업무마다 1단계 도구(`inventory.py` · `compare_xlsx.py --period` · `xlsx_profile.py`)를 돌리고, 사용자에게 판단 · 자주 틀리는 곳 · 걸리는 시간을 묻는다.
- **업무 사이 대사**를 직접 맞춰 본다(한 업무 결과 = 다른 업무 입력, 예: 명세 합계 = ERP 외상매출금, 결산파일 분개 = 정산표 수정분개). `read_values.py` 로 여러 파일의 칸을 한 번에 읽는다.
  맞으면 나중에 코드가 확인할 검산 후보가 되고, 안 맞으면 사람이 손으로 맞추던 곳이다.
- 난이도: 하 = 입력 1~2개 · 판단 1개 이하 · 표 구조 고정 / 중 = 입력 여러 개 또는 행 수 변화 · 판단 2~3개 / 상 = PDF · 글 판독, 판단 여럿, 다른 업무 결과 의존.
- 끝에 '확인 필요'를 먼저 물을 것(3개 이내)과 업무를 시작할 때 물을 것으로 나눠 적는다.

## 2. 만드는 순서

1. **파일럿 하나** - 입력이 단순하고 규칙이 분명하며 매 기간 반복되고 다른 업무에 기대지 않는 것(예: 은행 평가표 → 환산 · 평가 · 분개). 여기서 공통 도우미 · 폴더 규칙 · 재현 방법을 다진다.
2. **비슷한 유형 묶음** - 파일럿과 구조가 비슷한 평가 · 이월 파일들.
3. **판단이 많은 것** - 명단 · 회수 예상 · 계약 판단이 들어가는 파일.
4. **모으는 것은 뒤로** - 정산표 · 보고서 · 연결처럼 앞 업무 결과를 쓰는 것은 앞 업무 스킬이 선 뒤에.
   단, 사용자가 우선순위를 주면 따른다(예: "결산보고서가 핵심이니 먼저").
5. 구조가 매번 흔들리는 파일(손으로 덧붙여 온 파일)은 스킬보다 **양식 재구성**이 먼저일 수 있다 - 사용자와 상의.

## 3. 우산 스킬 (건 전체)

건 폴더의 `.claude/skills/<건>-<업무군>/` 에 둔다(고객 정보가 들어가므로 건 폴더 밖으로 옮기지 않는다). 담는 것:
- 건 전체 절차: 새 기간 폴더 만들기 · 진행판(받을 자료 · 만들 파일) 점검 · 자료 수령 점검
- 폴더 표준: 기간 폴더 구조, 업무별 산출 위치(담당자 폴더가 아니라 업무 항목 폴더 - 스킬이 찾기 쉽다)
- **업무 스킬 상태표**: 순서 · 업무 · 스킬 · 상태(예: "완료 - 2분기 재현 28/28칸 일치(날짜)" / "예정")
- 업무 스킬 공통 원칙(한 번만 적고 업무 스킬은 가리킨다): 지난 기간 최종본을 사본으로 이어받아 입력 칸만 갱신 · 원자료는 `Data_` 시트 · 계산은 수식 · 기간 판단만 묻기 · 지난 기간 자료로 돌려 지난 최종본과 대조
- 건 전체 재발 방지 체크리스트(`references/lessons.md`): 일정 · 자료 받기 · 계산 · 제출 전. 메일 · 검토 지적에서 뽑고, 기간이 끝날 때마다 더한다.

## 4. 공통 도우미 한 곳

업무 스킬마다 같은 코드를 복사하지 않고 우산 스킬의 `scripts/` 에 둔다.
- `<건>_config.py` - 경로, 기간 → 폴더, 법인 · 항목 목록, 파일 인식 규칙(새 법인 · 새 파일 이름이 생기면 여기에만 추가)
- `<건>_wp.py` - 지난 기간 최종본 찾기(후보를 최근순으로 보여 주고 사용자가 확인) · 사본 · 엑셀 재계산 · 대조 · 업무 항목 폴더 · 공유 확정값 읽기/쓰기.
  `wsc_xl.py` 를 바탕으로 건에 맞게 늘린다.
- 업무 스킬의 `build.py` 는 이 도우미를 불러 쓴다. 뼈대를 만들 때 `new_task_skill.py … --helpers "<우산 스킬>/scripts"` 를 주면
  `wsc_xl.py` 를 복사하지 않고 그 폴더를 불러오는 줄이 build.py 에 들어간다(도우미가 두 벌 생겨 한쪽만 고쳐지는 일을 막는다).
- 공유 확정값은 `W.shared_value(<기간 폴더>/…/_확정값.json, "USD", …)` 로 읽고 쓴다(build-rules.md 7절).

## 5. 공유 확정값

여러 업무가 같은 기간 값을 쓰면(기말 환율 · 기준 금리 · 확정 매출) 기간마다 한 번 확정해 한 파일에 둔다.
- 코드가 자료(예금 명세 환율 열 · 은행 평가표 환율)에서 후보를 빈도순으로 보여 주고 → 사용자 확정 → `<기간 폴더>/…/_확정값.json`.
- 이미 확정된 값과 다르면 멈춘다(바꾸려면 `--force`). '전 기간 환율이 남아 있던' 실수를 구조로 막는다.

## 6. 시험

- 기본: 지난 기간 원자료로 돌려 지난 기간 최종본과 칸마다 대조(N/N 일치)를 상태표에 적는다.
- 지난 기간에 양식이 바뀌어 대조할 수 없으면: 지난 기간 자료로 다음 기간을 만들고, 그 결과로 그다음 기간을 이어 만들어(연속 동작 시험) 이월 · 행 수 변화 · 참조 이동이 맞는지 본다. 실제 숫자는 첫 실제 기간에 사람이 검토한다.
- 그림 · 메모 · 배열수식이 있는 파일은 엑셀(COM)로 고치고, 고친 뒤 엑셀이 정상으로 여는지 확인한다.

## 7. 다른 건으로 옮길 때

로직이 같은 업무(예: 외화 환산 · 리스 상각)는 건 스킬에서 회사 고유 값을 설정 파일로 빼면 전역 스킬로 올릴 수 있다.
옮기기 전에 회사명 · 계정코드 · 사람 이름 · 금액이 남지 않았는지 `check_skill.py --forbid` 로 확인한다.
